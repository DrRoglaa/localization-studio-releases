# Help and support

[← Back to README](README.md)

I'm building Localization Studio as a solo developer. Clear reports help me reproduce issues and make focused improvements.

## Before opening an issue

1. Check the [release page](https://github.com/DrRoglaa/localization-studio-releases/releases) to see whether a public build actually exists.
2. Read the [README](README.md) and [roadmap](ROADMAP.md) for the current milestone and known limitations.
3. Search [existing issues](https://github.com/DrRoglaa/localization-studio-releases/issues) for an existing report.
4. Do **not** include real customer translations, API tokens, secret keys, or confidential files in an issue.

## Choose the right form

| Need | Start here |
| --- | --- |
| Something is broken in an available build | [Bug report](https://github.com/DrRoglaa/localization-studio-releases/issues/new?template=01-bug-report.yml) |
| An idea or workflow improvement | [Feature request](https://github.com/DrRoglaa/localization-studio-releases/issues/new?template=02-feature-request.yml) |
| Trouble installing or launching the application | [Installation help](https://github.com/DrRoglaa/localization-studio-releases/issues/new?template=03-installation-help.yml) |

For a bug report, please include the application version, operating system and version, exact steps to reproduce, expected versus actual behavior, and **sanitized** logs or screenshots if helpful.

## Security issues

**Do not disclose vulnerabilities or exploit details in public GitHub Issues.** See [Security](SECURITY.md) for private reporting guidance.

## Scope and response times

The project is under active development and currently has **no public installers**. I review feedback as an independent developer, so I cannot promise response times or implementation dates. Issues may be prioritized according to reproducibility, severity, and planned milestones.
